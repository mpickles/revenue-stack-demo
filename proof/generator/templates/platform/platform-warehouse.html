Why it is built the way it is

BecauseA budget alert only sends an email.
SoHard quotas are the limit.

A quota refuses the query. An alert tells you after the money is gone.

BecauseA bad number must never reach a report.
SoI chose dbt.

A failed test blocks everything after it by default.

BecauseA live warehouse query costs money on every page view.
SoScreens read saved copies.

The warehouse is only asked live for a drill-down, with a size cap.

What broke, and what I did about it

My first cost fix missed its target.

I assumed a few heavy tables were the problem. They were already rebuilding only new days. The cost was hundreds of small tables, each billed a minimum read.

FixI now measure the read per table before cutting anything.
The first scheduled run was refused.

The account the job runs as was not allowed to start it.

FixGave that account the one role it needed.
