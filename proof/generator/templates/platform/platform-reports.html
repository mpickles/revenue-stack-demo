How the number check works

Every report, in this order

  1. 1

    SQL works out every number a report may quote and puts them in one numbers block.

  2. 2

    The model writes from that block. If it needs a sum or a rate, it asks code to calculate it, and every formula is run again.

  3. 3

    The checker reads every number on every slide, tables and charts included, and looks it up in the block.

  4. 4

    A rounded number passes. Anything else is flagged. No numbers block, no build.

The checker gets checked too

If the checker itself breaks, the build fails and nothing ships.

Four tests that run every time the checker is built.
  • A clean deckEvery number matches the dataPasses
  • One planted wrong numberA single figure changed on one slideCaught
  • A number that is only in someone's notesNot in the data at allCaught
  • A deck with its numbers block missingNothing to check againstRefused

How one report gets made

  1. 1. It reads

    Warehouse performance tables, CRM leads, the work log, account changes, call summaries and meeting notes

  2. 2. A draft is made

    The model writes the story and the slide text from numbers that are already worked out

  3. 3. Code checks it

    Numbers come only from tested tables. Stale data and partial periods are flagged, and the numbers on each slide are checked

  4. 4. A person decides

    Reviews the packet slide by slide: reorders, edits, locks, cuts, adds context, then approves

  5. 5. It comes out

    A draft slide deck and its data sheet. A person sends it

Why it is built the way it is

BecauseA model will state a wrong number with total confidence.
SoCode works out every number. The model only writes.

Each figure a slide can quote is worked out in SQL first and handed over.

BecauseA true number from stale or half-finished data still misleads.
SoStale data and partial periods are flagged on the slide.

The reviewer sees the warning before the client ever could.

BecauseThe account lead knows things the checker does not.
SoA number that looks off warns. It does not block.

The lead can still approve. Only a report on part of a period is blocked, and only an owner can override that, with a written reason.

What I chose, and what I turned down

ChoseThe lead approves the story and the slide list. Then the deck builds.

Turned downBuilding the deck first and letting people edit it.

Why, and what it costThe first decks read like a data dump. Fixing a story is cheaper than fixing a deck.

ChoseThe account lead approves.

Turned downA second approval from a director.

Why, and what it costThe lead knows the account best.

ChoseA missing linked file is a warning.

Turned downStopping the build.

Why, and what it costOn the first live day, one unshared file stopped a deck that was otherwise fine.

ChoseMeeting notes are written straight into the running document.

Turned downA separate draft to copy across.

Why, and what it costOne less step for the lead. The cost: a client could see an entry before the team has finished it.

What broke, and what I did about it

A date was read as a number, and every draft was blocked.

The number checker read the "2026-08" in a date as the number 202 and rejected every report that month.

FixDates are stripped out before numbers are checked, with a test for it.
On the first full live day, fewer than half the decks built first time.

A missing file permission, a time limit that was too short, and a test run that had marked work as already done.

FixEach cause fixed that day, and every deck rebuilt and checked by hand the next.

Result

Hours saved per report: being measured

What I learned, and what I would do differently

My first checker failed open. When it could not find the numbers block, it accepted any number on the page, including ones from notes.
Next timeA check that cannot run must stop the build. It does now, with a test for it.
The first feedback on the decks was that they read like a data dump.
Next timeHave the account lead approve the story before any deck is built. That came two months in. It should have been day one.
The checker still misses a real number on the wrong label, and "up" where the figure went down.
Next timeThe tests print both gaps on every run, so they stay in front of me until they are closed.
