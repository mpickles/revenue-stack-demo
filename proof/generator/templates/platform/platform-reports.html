How one report gets made

Every report, in this order

  1. Code works out the numbers

    Every number a report may quote, in one block.

  2. The model writes

    Only from that block. Any sum it needs is run again by code.

  3. Code checks every slide

    Tables and charts included. No numbers block, no build.

  4. A person decides

    Reorder, edit, cut, then approve.

  5. A draft deck comes out

    A person sends it.

The checker gets checked too

If the checker itself breaks, the build fails and nothing ships.

Four tests that run every time the checker is built.
  • A clean deckEvery number matches the dataPasses
  • One planted wrong numberA single figure changed on one slideCaught
  • A number that is only in someone's notesNot in the data at allCaught
  • A deck with its numbers block missingNothing to check againstRefused

What went wrong, and what I do now

A date was read as a number, and every draft was blocked.The checker read the "2026-08" in a date as the number 202.
FixDates are stripped out before numbers are checked, with a test for it.
On the first full live day, fewer than half the decks built first time.A missing file permission, a time limit that was too short, and a test run that had marked work as done.
FixEach cause fixed that day. Every deck rebuilt and checked by hand the next.
My first checker failed open.When it could not find the numbers block, it accepted any number on the page.
FixA check that cannot run now stops the build, with a test for it.
The checker still misses two things.A real number on the wrong label, and "up" where the figure went down.
Still openThe tests print both gaps on every run, so they stay in front of me.
