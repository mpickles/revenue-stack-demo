How a sweep runs

Every client, in this order

  1. 1

    It reads the ad accounts and the tag containers, and crawls the site.

  2. 2

    It checks in a fixed order: account settings, conversion actions, the tag container, consent, click IDs, then whether lead counts agree within 10%.

  3. 3

    It rolls findings up to one row per client per rule.

  4. 4

    A person marks each row. Form and conversion tests only run when someone starts them.

Why it is built the way it is

BecauseA wrong edit to live tags can break a client's tracking.
SoThe auditor never publishes.

It has no permission to. A person acts on each finding.

BecauseNot every finding matters to every client.
SoA person marks each row.

Not relevant, or Checked, it works. The list is shorter next time.

BecauseCalling something broken needs proof.
SoEvidence comes first.

Paused tags are skipped, and nothing is called broken without it.

What I chose, and what I turned down

ChoseA fix arrives as an import file plus written steps.

Turned downLetting the system publish tag changes.

Why, and what it costA wrong publish breaks a client's tracking. The cost: a person does the last step by hand.

ChoseForm and conversion tests run only when a person starts them.

Turned downRunning them on a schedule.

Why, and what it costThey touch a client's live site. That should never be a surprise.

ChoseA page that answers three questions in order: is it working, how does it connect, what is missing.

Turned downA map of every tag.

Why, and what it costThe map looked clever and nobody could use it.

What broke, and what I did about it

The first version raised about 1,400 findings that were not real.

It counted the same problem once for every keyword it touched.

FixFindings roll up to one row per problem.
The audit screen was confusing and overwhelming.

That was my own verdict after using it for a week.

FixRebuilt as one page.

What I learned, and what I would do differently

1,400 findings is the same as none. Nobody reads them.
Next timeRoll up to one row per problem before showing anyone anything.
I built a map of every tag. It looked clever and nobody could use it.
Next timeStart from the checklist the team already works through. The rebuilt page does.
A screen once showed over a thousand broken conversions for one client. The bug was mine, not theirs.
Next timeNothing is called broken without evidence a person can open.
