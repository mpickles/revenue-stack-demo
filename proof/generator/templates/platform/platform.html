What I learned

In July I had never shipped a production app. In October I ran the go-live. Three things I had to learn to get there.

1

Moving data cheaply

Every query costs money, so the design has to read less.

  • Rebuild only what changed. The morning build went from about 30 GB a day to about 7.5.
  • A quota refuses a query. An alert only tells you after.
  • Measure before cutting. My one guess missed.
2

Designing for the person using it

I had to think like a product manager: what will they really do, and what happens at the edges.

  • 119 pages became 46 after the first pilot on real data.
  • A form for rerun requests was too technical. It became one button with plain names.
  • I assumed sane inputs. A budget was saved at 403% of its parent. Now it cannot be.
3

Directing an AI, strictly

Claude wrote the code. My job was the specs, the rules and the checks it could not skip.

  • Plan first, then build. A test for every behaviour.
  • Hooks, reviewers and branch rules, each added after something went wrong.
  • Never guess at a cause. Read the logs first.

How the way I work with Claude Code got stricter

  1. Aug to SeptChat and file drops

    One file overwrote another. Rule: a patch must match the old text exactly once.

  2. Early OctSpecs before code

    A plan I approve, a test for every behaviour. An outside reviewer found 12 issues in one phase.

  3. Mid OctHooks and guardrails

    Hooks block destructive commands and secret reads. No session ends on a failing check.

  4. Mid OctParallel sessions

    Branches collided. Rule: nothing merges without my go. A test fixer may never weaken a test.

  5. NovRelease branches

    Main only moves forward. I found the checks had been stopping before the real tests ran.

What went wrong, and what I do now

I promised time savings and timed nothing first.Two reporting cycles went by and that baseline is gone.
Next timeTime the old way before writing any code. Every deck now logs the minutes spent editing it.
Three checks failed open or never ran.The number checker, the automated tests and the backups. Each one said it was fine.
FixProve a check can fail before trusting it. Plant an error. Restore a backup.
On the first full live day, fewer than half the decks built first time.A missing file permission, a time limit that was too short, and a test run that had marked work as done.
FixEach cause fixed that day. Every deck rebuilt and checked by hand the next.
On launch day nobody could sign in.The new sign-in stored each person's ID in a different form from the one the app looked up.
FixBoth sides now use the same form. Patched the same day.
Production ran on old settings for a month.A manual step nobody could see. I forgot one redeploy.
FixNo step that lives in my head. Settings sit where the team can edit them.
