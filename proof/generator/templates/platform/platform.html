Why it is built the way it is

BecauseA model will state a wrong number with total confidence.
SoCode works out every number. The model only writes.

Each figure a report can quote is worked out in SQL first and handed over.

BecauseClient money is on the line.
SoNothing writes to an ad account.

Every change is a proposal a person approves. A wrong draft costs a minute. A wrong budget costs money.

BecauseI was the only builder, with no engineering team behind me.
SoTests block a bad load, so I am not the safety net.

I chose dbt because a failed test stops everything built on top of it by default.

What broke, and what I did about it

A date was read as a number, and every draft was blocked.

The number checker read the "2026-08" in a date as the number 202 and rejected every report that month.

FixDates are stripped out before numbers are checked, with a test for it.
On the first full live day, fewer than half the decks built first time.

A missing file permission, a time limit that was too short, and a test run that had marked work as already done.

FixEach cause fixed that day, and every deck rebuilt and checked by hand the next.
On launch day nobody could sign in.

The new sign-in stored each person's ID in a slightly different form from the one the app looked up.

FixBoth sides now use the same form of the ID. Patched the same day.

What I learned, and what I would do differently

I built first and timed nothing. The before number for hours saved comes from memory, not a stopwatch.
Next timeTime the old way for a month before writing any code.
The launch date slipped three times.
Next timeLaunch one workflow to two people first. Then widen.
A test run in production marked real work as done, and a client was skipped.
Next timeKeep test runs out of the live log from day one.
I built more screens than people could take in.
Next timeOne screen per job, and cut what confuses people in the first week.
