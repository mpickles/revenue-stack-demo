The problem

  • Client decks were built by hand. The same number came out different in different reports, because each was worked out in its own spreadsheet.
  • Reports, budget checks, search term reviews and meeting prep ate hours on every client, every month.
  • Nobody could see across clients. A broken tag or an overspend was found when someone happened to look.

Why it is built the way it is

Every choice came from a limit I was working inside.

BecauseA model will state a wrong number with total confidence.
SoCode works out every number. The model only writes.

Each figure a report can quote is worked out in SQL first and handed over.

BecauseClient money is on the line.
SoNothing writes to an ad account.

Every change is a proposal a person approves. A wrong draft costs a minute. A wrong budget costs money.

BecauseI was the only builder, with no engineering team behind me.
SoTests block a bad load, so I am not the safety net.

I chose dbt because a failed test stops everything built on top of it by default.

BecauseThere was a hard ceiling on what it could cost to run.
SoQuotas that refuse a query, and screens that read saved snapshots.

An alert only emails you after the money is gone. A quota says no.

BecauseEach account lead should only ever see their own clients.
SoAccess is enforced in the database, not on the screen.

Permissions are checked again on every action, and every export follows the same rule.

BecauseIt had to start on tools the agency already paid for.
SoIt began in the team's spreadsheets and grew into a web app.

The first version proved the idea where people already worked. The app came once it had.

The whole workflow

    What broke, and what I did about it

    A date was read as a number, and every draft was blocked.

    The number checker read the "2026-08" in a date as the number 202 and rejected every report that month.

    FixDates are stripped out before numbers are checked, with a test for it.
    On the first full live day, fewer than half the decks built first time.

    A missing file permission, a time limit that was too short, and a test run that had marked work as already done.

    FixEach cause fixed that day, and every deck rebuilt and checked by hand the next.
    On launch day nobody could sign in.

    The new sign-in stored each person's ID in a slightly different form from the one the app looked up.

    FixFound and patched the same day.

    Getting people to use it

    Measured from the start

    • Every reviewed draft logs how long the edit took and what was wrong with it.
    • That log is how drafts get better and how time saved gets counted.

    Taught, not just shipped

    • A walkthrough and a talk track for each workflow.
    • A demo mode with made-up data, and a help page for every feature.

    Cut back when it was too much

    • After the first real pilot the menus felt overwhelming.
    • I cut client tabs, trimmed the sidebar and hid features that were not ready.
